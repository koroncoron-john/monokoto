## 3. 状態定義

### カート状態 `cart_status`

| 状態 | 意味 |
| --- | --- |
| Active | 購入前の有効なカート項目 |
| Ordered | 購入処理済み |
| SoldOut | 購入前に在庫切れ等となった項目 |

### 予約・入金状態 `reserve_status`

| 状態 | 意味 |
| --- | --- |
| 入金済 | カード決済等が完了した取引 |
| 未払い | 現地払い、次回定期購入等の未入金取引 |
| キャンセル済 | 利用者または運営者が取り消した取引 |
| すべて | 管理画面の検索・絞り込み用 |

### 履行状態 `content_status`

| 状態 | モノ | コト |
| --- | --- | --- |
| 未発送 | 配送前 | 通常は対象外 |
| 発送済 | 発送・追跡情報登録後 | 通常は対象外 |
| 引渡済み | 現地引渡完了 | 受付完了相当として使われる箇所あり |
| 終了 | 取引完了 | 開催・受付完了 |
| キャンセル済 | 購入キャンセル | 予約キャンセル |

### 支払方法・状態

- コンテンツの支払方法: クレジットカード／現金
- 支払状態: お支払い済み／当日現金でお支払い
- マーケットの許可設定: 現地払いとクレジットカード／現地払いのみ／クレジットカードのみ
- 過去に存在した0円出品の値は削除済みですが、一部workflow名・分岐に痕跡があるため現行の0円取扱いを確認する。

## 4. 代表的な質問への現行回答

### Q. コンテンツは誰が作成できますか？

プレゼンターが `presenter` のコンテンツ管理から作成します。モノ、コト、ノートを選び、共通情報と種別固有情報を入力してプレビュー・公開します。マーケットオーナーと管理者は管理画面から確認・管理します。

### Q. モノの在庫はどこで判定しますか？

販売枠がある場合は `content_Mono.stock`、枠がない場合は `Content.10_mono_stock` から、キャンセル済みを除く購入数量合計を差し引きます。残数が0以下になると `soldout` が商品または販売枠を売切れへ更新します。

### Q. コトの予約金額はどう決まりますか？

`Content_Koto.price × Content_KotoReserve.total_user` が基本です。カード／現金はマーケットと予約画面の条件で選ばれ、予約記録に支払方法と支払状態を保存します。

### Q. カート購入と単品購入の違いは何ですか？

単品購入は1件の購入記録を直接作成します。カート購入は `cart_checkout_recursive` が各カート項目を順番に購入記録へ変換し、同じ `Group_id` でまとめます。領収書と完了メールもGroup単位です。

### Q. 定期購入はいつ次回作成されますか？

現行実装では、`create_monobuyer` が2か月後に次の購入記録を作り、キャンセル済みでなければさらに2か月後へ自分自身を予約します。商品ごとに周期を変更する設定は確認できていません。

### Q. 領収書はどう作りますか？

利用者が履歴画面から発行を要求すると、一時ログインリンク付きの領収書ページをMagic PDFが取得します。生成後のURLは、モノでは同じGroup IDの購入記録、コトでは対象予約へ保存されます。

### Q. デモデータは本番データと分離されていますか？

主要なマーケット、Content、コト開催枠、購入・予約には `demo_user` / `is demo` 条件があります。ただし全関連データに一貫してPrivacy Rulesが設定されているわけではないため、「完全に分離済み」とは断定できません。

## 5. 未確定事項・PM判断が必要な論点

| ID | 論点 | 現行実装から分かること | 必要な判断 |
| --- | --- | --- | --- |
| OPEN-01 | 定期購入周期 | 2か月固定で次回記録を作成 | 商品別周期が必要か、2か月が正しいか |
| OPEN-02 | 0円出品 | Option値は削除済みだが一部処理に痕跡 | 0円商品・イベントを正式対応するか |
| OPEN-03 | キャンセル可否 | コトは24/48/72時間前または不可、モノは主に不可 | 配送前キャンセル、返金、手数料の業務ルール |
| OPEN-04 | 退会時データ | 退会フラグ更新と一部削除処理あり | 法定保存対象、匿名化、再登録ルール |
| OPEN-05 | 管理対象範囲 | マーケット単位と全体検索が混在 | 管理者・オーナーごとの厳密なデータ境界 |
| OPEN-06 | 在庫同時更新 | 確定後に購入合計から売切れ判定 | 仮押さえ、同時購入、決済中在庫の仕様 |
| OPEN-07 | 決済失敗 | 定期購入停止・最新取引キャンセル・通知 | 再試行回数、猶予期間、復旧導線 |
| OPEN-08 | PDF保持 | URLを取引へ保存 | 保存期間、再発行、アクセス期限 |
| OPEN-09 | 通知既読 | read_usersリストに追加 | 全ユーザー通知かマーケット別か、削除・期限 |
| OPEN-10 | Live公開範囲 | 本資料はTestブランチ基準 | TestとLiveの差分管理・リリース承認手順 |

## 6. 回答時の確度ルール

- **確認済み**: BubbleのTestブランチ上でデータ、条件、アクションを確認できる。
- **実装から推定**: 名称や関連から目的は推定できるが、実ブラウザまたは業務ルール未確認。
- **要確認**: PM判断、外部サービス設定、Liveデータ、運用手順が必要。

PMへの回答では、必要に応じて「Testブランチの現行実装では」と前置きし、業務要件と実装事実を分けて伝えてください。
